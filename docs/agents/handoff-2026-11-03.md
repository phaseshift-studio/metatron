## TL;DR

The declaration facet (`?decq`), the builders that write it, and the law table's *reads* are coherent and green on the
suites that exercise them. Two things are **not** finished:

1. **`*plus?decq` (mtron-level read) still answers the instruction** for a per-contract inst address — a
   routing/dispatch defect, not a store defect (the store is proven good through the programmatic path).
2. **`catInstSetTest` has a 106-failure regression** that reproduces **alone** (derived inverses → `noobj`,
   `LawTable.lawsOf(...)` → `null`). Root cause not found; the bisect reduced it to "something since the last green
   gate", and the remaining suspects are `div`'s `[partial, pure]` law / guarded body and the boot-reset split.

Everything else below is either done+verified or a known, named red.

## 1. Architecture as it now stands

```
InstBuilder.create() / TypeBuilder.create()        (class-init: compose, stage)
        │  three writes per object
        ▼
PendingWrites  — RETAINED log (address → write), prefix-indexed, never consumed
        │  drainUnder(set vid) at mount · drainRest() at boot (object residue) · facets LAZY
        ▼
Machine.write(address, value)  →  the owning space's write door
        │
        ├─ ?docq  → QCollection.DocInstSet / OBJ_DOCS   (a real InstSet, per machine)
        └─ ?decq  → QCollection.DecInstSet              (NEW; a real InstSet, per machine)
        ▼
LawTable  — currently a READ CACHE + in-code rows (TABLES singletons, per-table memo)
```

**Direction agreed with the owner**: `LawTable` should be *read-only* — `public static` `LawTable.Helper` methods that
answer by reading `DecInstSet` through the standard door (`Machine.read(addr.addQ(DECQ))`), keeping a cache only where
it pays. No store, no process-wide maps. The store side (`DecInstSet`) is now in place; folding the table layer is the
remaining refactor.

## 2. Done and verified this session

### Declaration facet — `?lawq` → `?decq`, one write funnel
- `QCollection`: `DECQ`, `DECQ_PATTERN`, `DECQ_TID`, `decQ()`, `decId`, `decOf`, `decWrap`. No `?lawq` spelling remains.
- **`DecInstSet`** (new, inside `QCollection`, mirror of `DocInstSet`): the `?decq` store as a per-machine `InstSet`,
  keyed by the declaration address. `decQ()` is backed by it; no anonymous `memSpace`, no static Java map.
- `decOf(fURI)` is `Machine.read(id.addQ(DECQ))`; `decWrap` is `Machine.write(id.addQ(DECQ), rec)`. **One door.**
- `decQ().preRead` resolves the key as `Inst.Helper.operationTid(bare.big())` (the writer's spelling), publishes from
  the retained log on a miss, then falls back to the contract-specific address. Returns `noobj`, never the inst.

### Builders (the write side)
- `AbstractObjBuilder<B,O>` (new) with `tid/vid/description/examples/laws/inverse/derivation`; `InstBuilder` and
  `TypeBuilder` extend it. `Type.Builder` (the old nested bridge) is **deleted** — 61 files / 319 call sites migrated.
- `InstBuilder.create()` composes `(tid, inst)`, `(docq(tid), doc)` **and at the bare operation address**, and
  `(decq(operationTid(tid)), claim)`. `argDocs(Map<Obj,String>)` added for `rec(...)` argument lists.
- `TypeBuilder` carries docs inline (`desc`, `example`, `refinement`, `slots`, `constructor(…, Map)`), and `.create()`
  writes type + docq + decq(the algebra).
- `docWrap(instC(...))` migration: **`Obj.java` 75/75**, `Str/Real/Uri/NoObj` 8/8; losslessness proven by string-literal
  extraction (329/329 for Obj, 34/34 for the four). `docWrap(Type, …)` has zero call sites.
- `mFluent`: `div_`/`mod_` exist (instance + `StartLess`).

### Law vocabulary as data
- `law::T` at `/m/law`: a uri is a law when `/m/law/<label>` holds one; `Law.register()` publishes each law's value,
  `?docq` (javadoc) and `?decq` (`[inst => lst(shapes)]`). `[law => union(…)]` replaced by `[law => law::T]`; readers
  (`Cut`, `LawTable`, `mTypes.axiomsOf`, `LawCensusTest`) expand the type-valued slot to "any law".
- `mTypes.LAW_TYPE` predicate: `guard + preconstructed LAWS_SET + store fallback` (so a newly written law is admitted).

### The law table and boot lifecycle
- `LawTable.reset()` (memo only): `STORE_DERIVATIONS`, `LOG_DERIVATIONS`, per-table algebra memo. **Do not clear the
  "what has been loaded" bookkeeping** (`STORE_DERIVATIONS_AT`, `_WAS_LOADED`, `LOG_SNAPSHOT`, `LOG_DECLARATIONS`) —
  clearing those makes the ring normalizer lose its derivations (`InstTest.testRingAlgebra` regressed exactly so).
- Boot publishes **per boot**: `mInstSet.setup()` calls `mTypes.declareAlgebras()`/`declareAxioms()` (their recs name
  live insts, so a class-init copy goes stale).
- `BootLoader.resetMemos()` — the boot door: `LawTable.reset()` + lazy-hook off; called before any mount, then
  `PendingWrites.install()`. **It must not clear the staged log or the build-time indices.**
- `BootLoader.resetCaches()` — the explicit "blank JVM" door: `resetMemos()` + `PendingWrites.reset()` +
  `InstBuilder.reset()` + `TypeBuilder.reset()`. Only safe when class-init staging will run again.
- Lazy facet publication: `?docq`/`?decq` are published by the first reader that misses them
  (`QCollection.LAZY_PUBLISH`, installed at boot; `PendingWrites.publish`).
- `drainUnder` publishes **only what the space does not answer** (objects): a live registration must never be replaced
  by a staged copy (cross-boot identity bugs: `spaceChat`, `MariaDB/MySQL/Postgres/SQLite` deserialization, `ide`).
- Type identity: a type is created **once per JVM** (`DATETIME_TYPE`, `LLM_CHAT_RESULT_TYPE`, `LLM_SKILL_TYPE`,
  watermark, message types). Re-creating one per `setup()` gave an address two objects and broke every type test that
  closed over the address.
- `llmInstSet.setup()` mounts **math first** (`InstSet.importInstSet(MATH_ISA_TID)`) before building the types that
  state `time`/`runtime` slots — the import used to sit *after* `chat_result`, which is how its slots came out as
  `real::T`/`[noobj]` holes.

### `div` / `mult` (int) — mathematically honest
- `div`: **no `inverse`**; laws `[partial, pure]`; body returns `noobj()` on a zero divisor (no `Infinity` saturation);
  derivation: `a.div(b).mult(b).plus(a.mod(b)) = a`.
- `mult`: **no `inverse`** (`int` is a `mult_monoid`, not a group: `7.div(2).mult(2) = 6`).
- Stale "one-way retraction" notes removed from `catInstSetTest` and `LawTable`.

- `DecqReadProbeTest` (new, logs the four spellings — promote to assertions when the dispatch is fixed).

Verified green (isolated target): `InstTest` 156, `LawCensusTest` 7, `AlgebraTest` 5, `AlgebraToolTest` 8,

## 3. Open defects — evidence

### 3.1 mtron-level `?decq` for inst addresses (the user-facing bug)
Probe output (`DecqReadProbeTest`, after `DecInstSet`):

```
/m/int?decq                              -> the algebra rec        ✓
/m/inst/plus?decq                        -> redirect rows {plus?/m/int<=/m/int&decq(int::T), …}   (q dropped)
/m/inst/plus?rng=/m/int&dom=/m/int&decq  -> plus?/m/int<=/m/int&decq(int::T)                      (the INST)
```

The store answers when asked programmatically (`decOf`/`Machine.read` in Java tests), so this is **dispatch**: for a
per-contract inst address the `?decq` q is consumed by address resolution before the q-proc is consulted. Next probe:
log, in `Machine.read`'s q dispatch, the space chosen and the q-proc tid matched, for `/m/int?decq` vs
`/m/inst/plus?…&decq`. Whatever differs there is the bug; it will also explain the redirect-row answer (unknown q is
dropped and the base address resolves).

Note: `Machine`/`BasicMachine`/`MachineSpace`/`variableStack` register only `docQ()`; the instsets register
`docQ()`+`decQ()` (`AbstractInstSet` ~230–245 — make that a union so no space can be missing it).
