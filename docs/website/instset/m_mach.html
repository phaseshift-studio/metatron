    binder::T refines /m/mach/component::T /m/mach/component/binder 
    component::T@/m/mach/component/binder
    ↳component::T ?[{?}machine=>machine::T]

    nominal the binding contract of resolver::T — the collaborator that turns one selected candidate into the instruction a call becomes, or rejects it: it binds the candidate's generics to the lhs, gates it on the lhs domain, and resolves its arguments (compiling nested code args), returning null when the candidate cannot be made concrete; because a candidate that fails to bind must not be selectable, binding gates selection rather than following it, which is why a binder is a strategy inside the resolve stage and never a stage of its own. The candidate arrives already shaped with the call's dom/rng hints — that shaping is the selector's rule.

    ↳component::T ?[{?}machine=>machine::T]

    structural the compiler contract of machine::T — a machine's lowering axis, source to code::T, composed of four atomic overridable stages: the stages are the vocabulary and these rec entries are the wiring, all optional and each defaulting when absent, so a compiler is its composition rather than an algorithm. compiler.apply runs the default schedule — parse → rewrite → resolve → type — each stage handed the whole of what the last produced and returning the same, and the processor is the sibling that then runs what the compiler produced. Only the parse stage accepts anything but code — source text, or an already-parsed obj it lifts as it stands instead of re-reading; every stage returns code::T. A compiler is constructed from its stages, and a bare compiler::[=>] is the default compiler.

    args: 
      {?}typer => 'the fourth stage — the per-machine runtime type assertions (inst_dom, inst_rng, type_pred), carried in the machine instead of a global TypeCheck registry'
  {?}resolver => "the third stage — the walk that threads each inst's range into the next inst's domain, delegating per inst to a selector (which candidates) and a binder (make one concrete): scoring_resolver::T by default"
  {?}parser => "the first stage — source text to obj, and the identity for anything that is not a str, so a compiler accepts a program's text or its parsed obj alike: mtron_parser::T by default"
  {?}rewriter => 'the second stage — the code::T to code::T lowering that runs before any type is resolved: fixpoint_rewriter::T by default (every registered rewrite rule to a stable fixpoint), identity_rewriter::T for a compiler that wants no rewrites'

    discovery::T refines /m/rec::T /m/mach/component/network/discovery 
    rec::T[?[status=>bool::T]]@/m/web/discovery

    structural a discovery protocol — a source of machine endpoints for the one roster/machine table. Existence is its interface: construction starts it, deletion stops it, and it publishes no verbs. It requires exactly one field, status, because liveness is the only thing a consumer cannot work out for itself. Where an endpoint was learned is irrelevant: every protocol writes into the shared table rather than exposing a listing of its own, so peers are generated from one consolidated index. Distinct from /m/web/discovery, which is the protocol surface it discovers over

    args: 
      status => 'the one field every discovery protocol must answer: true while it is live and finding machines. Derived on read, never stored — a responder whose interface went away does not announce itself'

    structural a machine integrates language, structure, and process into one context for action within metatron. machines form a nested stack: a parent machine's state is reachable from its children, and a parent defines the scope of a child machine's access to resources. machines communicate laterally through the network component, where a peer group forms a shared computing workspace that is garbage collected when the machine is popped off the parent stack. the absolute root of the metatron graph (/.) is the root machine.

    structural a machine's network: the endpoints the system knows about, the peers the current machine has dialed, and the handlers that discover them. Membership is declared, never emergent — a uri must not be able to make itself a peer merely by being addressed — and it is accumulating, so a child machine unions its own level over its parent's.     destructive — the one machine instruction that closes what it leaves, where move leaves it standing and reachable by address. It discards the machine the code is running in and lands on that machine's \(..\).     mint a machine at an address in the machine tree and make it current. Constructive — it adds a machine, where move only chooses one.
