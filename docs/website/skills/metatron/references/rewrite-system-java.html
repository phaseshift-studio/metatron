    Java-side rewrite infrastructure — Rewriter, RewriteBuilder, InstSet.Helper.rewriter, Code.rewrite() loop, space-aware native pushdown, custom rewrite functions, and registration patterns
    rewrite-system-java.md

    Rewrite System (Java)

    Package map

    algebra/rewrite/Rewriter.java       ← fixed-window pattern matcher + replacement engine
algebra/rewrite/RewriteBuilder.java ← fluent builder for space-aware native rewrites
algebra/rewrite/CommonRewrites.java ← shared rewrite utilities
isa/m/type/InstSet.java             ← InstSet interface, Helper.rewriter() factory
isa/m/type/Code.java                ← Code.rewrite() — the rewrite loop
isa/m/mInstSet.java                 ← /m rewrites (theory_unit_removal, law_involution, law_absorbing, ..., split_merge_collapse, ...)
isa/tble/tbleInstSet.java           ← SQL rewrites (sql_count, sql_where, sql_limit, ...)
isa/grph/grphInstSet.java           ← Gremlin rewrites (gremlin_count, gremlin_where, ...)
isa/dcmnt/dcmntInstSet.java         ← MongoDB rewrites (mql_count, mql_where, ...)

    Lifecycle — when rewrites fire

    expression.parse()        → Call / Code
        │
        ▼
Code.resolve(lhs)                       [Code.java:98]
        │
        ├─ this.rewrite()               [Code.java:102]
        │   │
        │   ├─ iterate ALL InstSet spaces in Router
        │   │   └─ r.apply(currentCode) for every rewrite Inst
        │   │       └─ replace if result.isCode()
        │   │
        │   └─ repeat until fixed point (hash stabilizes)
        │
        └─ InstResolver.resolveCode()   [InstResolver.java:105]
            └─ resolve each Inst in the rewritten list

    Rewrites run before instruction resolution. This means domains/ranges in the instruction list are still generic (#::T) when rewrites fire — call .resolve(noobj()) on extracted code if you need concrete types.

    Registration

    Rewrites are registered in an InstSet under the uri(REWRITE) key during setup(). A machine's pool is its instruction set's union, Machine.current().instset().rewrites() (the default of Rewriter.rewrites()): its own level first, then the instruction sets it imported, then the enclosing machine's, each rewrite once by its tid, so a nearer level SHADOWS the same tid. The default compiler stage, fixpoint_rewriter::T, applies the pool in order to a fixpoint (FixPointRewriter.apply):

    for (final Inst r : orderedRules(this.rewrites())) {     // analysis rules last, registration order otherwise
    final Obj rewritten = r.apply(code);
    if (rewritten.isCode())
        code = rewritten.asCode();
}

    A rewrite is an Inst whose function takes a Code and returns a Code. If the result is a Code, it replaces the current code for the next iteration. If the result is not a Code (e.g., noobj, a single Inst), it is discarded and the code is left unchanged.

    Switching a rewrite off

    A rewrite is switched off by its shadow (Marko, 2026-11-10), so the pool still lists what is off. inactive?inst<=inst answers the identity on code under the rewrite's own tid, carrying the rewrite as [inactive=>rewrite]. active?inst<=inst answers the rewrite a shadow carries (Inst.Helper.shadowed), and an active rewrite as it is. Written into a machine's own level, the shadow is the same identity as the inherited rewrite. So it stands in the rewrite's place for that machine and its children, and the fixpoint applies it as the identity, while every other machine keeps the rewrite. A noobj write at the rewrite's address deletes the shadow, and the inherited rewrite answers again:

    final Inst shadow = Processor.Helper.apply(rule, instB(INACTIVE_INST_TID, lst())).asInst();
child.instset().write(rule.tid(), shadow);       // off in the child, and listed in its pool
child.instset().write(rule.tid(), noobj());      // on again: the inherited rewrite answers

    An instruction written under the tid of a rewrite the set answers IS that rewrite (AbstractInstSet.write). A code dom alone makes no rewrite: code's own operations (end, id, update) are instructions.

    From mtron, every table of a machine's instruction set has a door at ~/instset/<table> (rewrite, inst, type, const). A read there answers the live table (the effective view, nearer levels shadowing), and <table>/<name> its entries by name, a rewrite or an instruction by its tid's name and a type or a const by its vid's, walked as a path or projected with >> (AbstractInstSet.at). A write at ~/instset/<table>/<name> lands in the machine's own level (MachineSpace routes it to BasicInstSet.write) and declares a difference: an entry overrides what the level inherits, while the inherited entry itself adds nothing and noobj clears the level's own entries of that name, so a read written back changes nothing. An argument that is an instruction is code, applied to the lhs, so a literal instruction is written BLOCKED, addr -> |inst (addr.ref(block(inst))). A block hands its argument over as written, an expression unevaluated, so an instruction an expression computes (a shadow) is written with to, which writes the obj flowing in:

    *~/instset/rewrite/law_absorbing.inactive().to(~/instset/rewrite/law_absorbing)    off here, and listed
*~/instset/rewrite/law_absorbing.active().to(~/instset/rewrite/law_absorbing)      on again: the override goes
~/instset/rewrite/law_absorbing -> noobj                                           on again, the same way

    An instruction set's own path walks its rec: what no table holds is the rec's, so */m/math/cat/rewrite answers what */m/math/cat>>rewrite does, the set's live rewrites.

    Rewrite styles

    1. Rewriter.search().match().rewrite() — fixed-window pattern replacement

    Matches a concrete sequence of instruction TIDs against a sliding window, then replaces the matched slice with a new instruction list. The rewrite function receives a Map<Inst, Inst> mapping pattern instructions to matched source instructions.

    // geoRewrite.pushdown: over a space with native spatial support, the generic operator becomes the space's own
InstSet.Helper.rewriter(GEO_REWRITE_TID.extend("native_" + nativeTid.name()), code -> {
    if (!readsNativeSpace(code, nativeSupport))
        return code;
    return code.selfJVM(RewriterBuilder.search(code.insts())
            .match(instA(genericTid).insts())                       // match [generic]
            .rewrite(matched -> matched.values().stream()
                    .map(actual -> instB(nativeTid, actual.args()))  // the native operator, same args
                    .toList())).asCode();
})

    A rewrite whose rule is only instructions states it as data: a [lhs => rhs] rec, the declared argument of its own /m rewrite (one rewrite per rule), built with the rules overload of InstSet.Helper.rewriter. Its body hands the rules to Law.Helper.rewrite(code, rules, gate), which applies each equation with Call.Helper.update wherever the gate admits the matched run. else_after_count's [count().else(#::T) => count()] needs no gate, so it drops the dead else after a total count wherever the rule matches:

    docWrap(InstSet.Helper.rewriter(M_ISA_REWRITE_TID.extend("else_after_count"), ELSE_AFTER_COUNT, (code, rules) ->
        Law.Helper.rewrite(code, List.of(rules), (scanned, start, length) -> true)), "…")

    A law's rewrite binds its rules to the law's claimants (Law.Helper.claimed) and writes its gate beside them, reading the law at the carrier flowing into the run (Rewriter.Helper.carriers). The rule rewrites and their gates are described in the cat-instset-mtron reference.

    match(List<Inst>) — pattern instructions. instA(tid) creates a bare match instruction (no args, no f). Matching uses instsMatch(): TIDs must be compatible via tid.test(), args are compared by position, and ?.test(source) tests unresolved args against source.

    match(List<Inst>, Predicate<List<Inst>>) — adds a runtime guard. The function receives the matched source instructions; return false to skip the rewrite.

    repeat() — keep applying the rewrite until the instruction list stabilizes.

    matchCC() — also match coefficients (disabled by default — only TIDs and args).

    allow / disallow — per-rewrite URI-based gate lists.

    Rewrite function — Function<Map<Inst, Inst>, List<Inst>>. The map keys are the match pattern instructions; values are the matched source instructions. Return the replacement instruction list.

    Key limitation: fixed-length matching only. The pattern [A, B] matches exactly two instructions. There is no variable-length prefix/suffix capture.

    2. DBRewriteBuilder — space-aware native operation pushdown

    A fluent builder for rewrites that replace generic instruction chains with native database operations. The key difference: the rewrite checks which space the data lives in, and only fires when it's the right backend.

    RewriteBuilder.forDatabase(tbleSpace.class)
    .tid(TBLE_ISA_REWRITE_TID.extend("sql_count"))
    .match(FROM_INST_TID, COUNT_INST_TID)        // match [from, count]
    .optimize("from_count", (space, dp, coeff) -> {
        String table = dp.collection();
        try (Statement stmt = space.sjvm().createStatement();
             ResultSet rs = stmt.executeQuery(
                 "SELECT COUNT(*) FROM " + table)) {
            return rs.next() ? jnt(rs.getInt(1)).c(c -> c.mult(coeff)) : jnt(0);
        }
    })
    .build();

    Builder methods:

    MethodPurpose
    forDatabase(Class<S>)Restrict to a specific space type
    tid(fURI)Rewrite instruction TID
    rng(fURI)Result type (e.g., INT_TID)
    match(fURI...)Sequence of instruction TIDs to match
    matchPredicate(Predicate)Runtime guard on matched instructions
    matchSpacePredicate(BiPredicate)Guard with access to the typed space (e.g., check table exists)
    optimize(name, NativeOptimization)Native execution lambda (space, dataPath, coeff) -> Obj
    optimizeWithURI(name, NativeOptimizationWithURI)Native execution with expanded fURI
    build()Produce the Inst for registration

    Execution flow:

    1. Rewriter.search().match().rewrite() finds a matching instruction sequence
    2. The rewrite function checks spaceType.isInstance(space) — wrong space type → skip
    3. matchPredicate and matchSpacePredicate guards run — fail → return original unchanged
    4. Native lambda executes against the database, receiving the coefficient for cardinality tracking
    5. The matched sequence is replaced with a single native instruction

    3. Custom Function<Code, Code> — full AST inspection

    When the RewriterBuilder API's fixed-window matching doesn't fit (variable-length prefix capture, conditional restructuring), use InstSet.Helper.rewriter() directly with a custom function:

    InstSet.Helper.rewriter(M_ISA_REWRITE_TID.extend("explain_profile"),
    code -> {
        final List<Inst> insts = code.insts();
        if (insts.isEmpty() || insts.size() < 2) return code;
        final Inst last = insts.getLast();
        if (!last.tid().basePath().equals(EXPLAIN_INST_TID)) return code;
        // Extract everything before explain() as a Code argument
        final List<Inst> preceding = new ArrayList<>(insts.subList(0, insts.size() - 1));
        final Code precedingCode = MCode.of(preceding).resolve(noobj());
        // Replace the whole chain with a single compute instruction
        return code.selfJVM(List.of(
            instC(computeTID, lst(block_(precedingCode).tryToInst()),
                (lhs, inst) -> str(explainTable(inst.arg(0).asCode())))
        )).asCode();
    })

    Pattern: inspect the full instruction list, decide whether to transform, return either the original code (no-op) or code.selfJVM(newInsts).asCode() (replacement).

    Key points:

    • code.selfJVM(newList).asCode() wraps a new instruction list into the same Code frame
    • The inline lambda receives the rewritten code as inst.arg(0) — resolved and concrete
    • Keep replacement logic terminal-free; rewrites execute before any Console exists
    • Dynamic dispatch is normal for inline instructions — they resolve at runtime

    Common patterns

    Returning the original unchanged

    If the rewrite condition isn't met, return the input code directly. The rewrite loop sees no change and moves on:

    if (!last.tid().basePath().equals(EXPLAIN_INST_TID)) return code;

    Replacing instructions inline

    return code.selfJVM(newInstructionList).asCode();

    Creating a native instruction with domain/range

    For native operations, set dom(NOOBJ_TID.zero()) (zero cardinality) so the instruction never fires on an empty stream — it either runs natively (one-shot) or not at all:

    instC(tid.dom(NOOBJ_TID.zero()).rng(INT_TID), lst(uri(fURI)),
    (lhs, inst) -> executeNative(inst.arg(0).uriValue()))

    Resolving extracted code for concrete types

    Extracted code still has generic domains. Resolve it before passing to formatters:

    final Code precedingCode = MCode.of(preceding).resolve(noobj());

    The rewrite instruction type

    InstSet.Helper.rewriter() creates the instruction:

    public static Inst rewriter(final fURI tid, final Function<Code, Code> rewrite) {
    return instC(tid.dom(CODE_TID).rng(CODE_TID.maybe()), lst(),
        (lhs, inst) -> rewrite.apply(lhs.asCode()));
}

public static Inst rewriter(final fURI tid, final Rec rules, final BiFunction<Code, Rec, Code> rewrite) {
    return instC(tid.dom(CODE_TID).rng(CODE_TID.maybe()), lst(rules),
        (lhs, inst) -> rewrite.apply(lhs.asCode(), inst.arg(0).asRec()));
}
    • Domain: CODE_TID — receives a Code
    • Range: CODE_TID.maybe() — returns an optional Code (noobj = no rewrite)
    • Body: calls the provided Function<Code, Code>, or the BiFunction<Code, Rec, Code> with the rules
    • Rules: the second overload declares its rules as the instruction's one argument, a value rather than a type, so it resolves with them bound; the body reads them off inst.arg(0), so the argument is their one source

    The returned Inst is registered under uri(REWRITE) in the instset. During Code.rewrite(), it's applied with the current code as lhs.

    Convenience: InstSet.Helper.rewriter() with Rewriter

    The common docWrap(InstSet.Helper.rewriter(...), ...) pattern:

    docWrap(
        InstSet.Helper.rewriter(tid, code ->code.

selfJVM(
        Rewriter.search(code.insts())
        .

match(pattern)
            .

rewrite(replaceFunc)
    ).

asCode()),
        "description"
        )

    docWrap registers the rewrite under uri(REWRITE) and attaches the description string as the ?docq query parameter on the rewrite TID.
