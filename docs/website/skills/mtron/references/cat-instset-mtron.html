    The category graph at /m/math/cat: every type is an **object** (a vertex) and every inst is a **morphism** (an edge). Lift a type with .as(object::T) to read the morphisms incident to it (morphed_to out-edges, morphed_from in-edges); lift an inst with .as(morphism::T) to read its endpoints (src dom, trgt rng) and its whole-graph analysis (family, contested, orbit, position, inverse). TRIGGER: When reading a type's incident morphisms or a morphism's endpoints, when reasoning about a morphism's siblings / inverse / connected component, when classifying an edge's coefficient shape (form), set-theoretic class (class), or declared process laws (law), when wiring the algebraic theories (ring / field / rig / group / monoid / boolean / lattice), when adding a law-driven rewrite — the category *is* the rewrite table — or when lifting code itself into the graph (path::T for value code with rewrite edges, abstraction::T for its pointwise type-level image) to navigate, prune, or plan rewrites.
    cat-instset-mtron.md

    the category graph (/m/math/cat)

    /m/math/cat realizes types and insts as a category: types are the objects (the vertices), insts are the morphisms (the edges), and an inst's dom/rng are its source and target endpoints.

    mtron> import(/m/math/cat,cat)
...

    The category is not part of the default boot profile: the import above is what mounts /m/math/cat and binds the cat: alias, and none of the lifts below resolves on a machine that has not imported it.

    The lift is a type constructor. An object is constructed from a type and a morphism from an inst. This structure is called the cat-graph.

    A vertex is a type lifted to object::T; an edge is an inst lifted to morphism::T. Every morphism is classified on four axes — form (its n-tid coefficient shape), class (its set-theoretic class), position (its place in the graph), and law (the algebraic laws it obeys) — and every object carries the structural theories it models. Those same declarations are what the rewriter stage consumes (see the declared rewrites).

    A law is either structural, declared at an object, or process, declared at a morphism. Both kinds of declaration are consumed by the later lifts: when code::T is modeled as a vertex on a graph of rewrite edges, the rules a vertex may take are read from exactly these declarations (see the declared rewrites and the third lift).

    the algebraic theories

    An object can model several algebraic structures. object::T>>law is a rec keyed by the name given to each instance at declaration, and each role holds a !* (auto_from) pointer to the live operation rather than a copy: the graph holds the references, and a role dereferences transparently on >> (...>>law>>ring>>add yields the inst). The first example above is the int case in full: its law rec declares a ring and the three constituent group/monoid instances. theory::T is the nominal super-type grouping them:

    typeroles (fields)what it asserts
    ring_theoryadd, mul, zero, one\(\langle R, +, \cdot, 0, 1 \rangle\): \(+\) an abelian group, \(\cdot\) a monoid, \(a \cdot (b + c) = a \cdot b + a \cdot c\)
    field_theoryadd, mul, zero, one, inv\(\langle F, +, \cdot, 0, 1, {}^{-1} \rangle\): a commutative ring where every non-\(0\) element has a multiplicative inverse, \(x \cdot x^{-1} = 1\)
    rig_theoryadd, mul, zero, one\(\langle S, +, \cdot, 0, 1 \rangle\): additive and multiplicative monoids, \(\cdot\) distributive over \(+\), no additive inverses
    group_theoryop, id, inv\(\langle G, \cdot, 1, {}^{-1} \rangle\): \(g \cdot g^{-1} = g^{-1} \cdot g = 1\)
    monoid_theoryop, id\(\langle M, \cdot, 1 \rangle\): \(m \cdot 1 = 1 \cdot m = m\) and \((m \cdot n) \cdot p = m \cdot (n \cdot p)\)
    boolean_theoryor, and, not, zero, one\(\langle B, \lor, \land, \lnot, 0, 1 \rangle\): a complemented distributive lattice, \(b \lor \lnot b = 1\) and \(b \land \lnot b = 0\)
    lattice_theorymeet, join, bottom, top\(\langle L, \sqcap, \sqcup, \bot, \top \rangle\): every pair of elements has a meet and a join, bounded by \(\bot\) and \(\top\)
    semilattice_theoryop, id\(\langle S, \sqcup, 0 \rangle\): an idempotent commutative monoid (one side of a lattice)
    near_ring_theoryadd, mul, zero\(\langle N, +, \cdot, 0 \rangle\): \(+\) a group, \(\cdot\) a monoid, one-sided distributivity, no multiplicative \(1\)

    the morphism fields

    fieldwhat it is
    namethe operation's name
    objthe inst this morphism wraps (the edge itself)
    formthe n-tid coefficient shape — see the form axis
    classthe set-theoretic class (endo, iso, auto, mono, epi, section, retraction)
    srcthe source object (the morphism's dom)
    trgtthe target object (the morphism's rng)
    derivationthe declared defining equation, lhs ↦ rhs, when the operation is derived (see the declared rewrites)
    lawthe declared process laws the morphism obeys (see the process laws)

    the form axis

    form is the morphism's n-tid coefficient shape — the (dom_c, rng_c) pair in regex notation:

    formwhat it is
    initialmaps nothing to objs (dom_c = 0)
    terminalmaps objs to nothing (rng_c = 0)
    mapperone-to-one obj transformation (dom_c = rng_c = 1)
    filterconditionally passes or drops an obj (dom_c = 1, rng_c = {0,1})
    flatmapperone-to-many obj transformation (dom_c = 1, rng_c > 1)
    scattermaps an obj to objs (rng_c = {0,})
    gathermaps objs to objs (dom_c = {0,})
    reducergathers objs into a single output (rng_c = 1)
    forksplits objs across parallel streams
    joinmerges parallel streams into a single stream
    catcherintercepts a fail obj for recovery
    standardan instruction with no well-defined classification

    Two forms collapse onto the stream-ring's function subrings for the rewrite algebra: scatter is the linearized one-to-many (flatmapper) and join is the many-to-many merge (gather). On that projection, a coefficient floats through mapper / filter / flatmapper — the floatable run — and is anchored by reducer / gather — the blocked cut (see the process laws).

    the dual incidence

    src/trgt and morphed_to/morphed_from are the same relation seen from opposite sides:

    fromdom side (out)rng side (in)
    an objectmorphed_tomorphed_from
    a morphismsrctrgt

    morphed_to(A) is \(\{ f \mid \mathrm{src} (f) = A \}\); morphed_from(A) is \(\{ f \mid \mathrm{trgt} (f) = A \}\). Composing them round-trips — from an object to its edges and back, or from an edge to its endpoints and back.

    the analysis sub-block

    analysis is one lazy auto() — evaluated with >>analysis. Inside it, each stat is itself lazy:

    fieldwhat it is
    familythe same-name siblings: \(\{ g \mid \mathrm{op}(g) = \mathrm{op}(f) \}\) — every registration of the same operator
    contestedthe witness edges behind the ambiguous / incomparable labels — the competing siblings
    orbitthe connected component of the source object in the reversible core — all objects reached by edges that exist in both directions
    positionthe edge's place among its siblings (a subset of the six kinds below)
    inversethe opposing edge \(f^{-1}\) with \(f \cdot f^{-1} = 1\) (only when a declared inverse exists)
    combinerthe edge a reducer's partials recombine through, \((a \uplus b) \cdot r = (a \cdot r \uplus b \cdot r) \cdot \mathrm{combiner}(r)\) — computed, never declared: a fold declaring monoidic + commutative is its own, a fold defined by its derivation names the fold that defines it (count ↦ sum, order ↦ kmerge); a keyed fold (group) recombines pointwise through a chain — sum, then a per-key fold — that no single edge names, so it has none here

    the six edge kinds

    position classifies an edge against the rest of the graph into up to six labels:

    kindthe relation to the graph
    duplicateanother morphism of the same family maps the same dom to the same rng
    ambiguouscontested by an incomparable sibling that overlaps it — dispatch has no winner
    incomparablecontested by an incomparable, disjoint sibling — dispatch stays total
    couplingan edge in the opposite direction links the same two objects — a candidate inverse pair
    isochainendpoints linked by a chain of couplings — one orbit of the reversible core
    retractmutually reachable and round-trip idempotent — a subobject retraction

    orbit is the transitive closure of coupling — the connected component of the reversible core (the subgraph of edges that exist in both directions). It is a reachability class, coarser than isomorphism (which needs the round trip to be idempotent → retract) and finer than raw incidence.

    the class axis

    class classifies a morphism set-theoretically — as self-mapping, invertible, or split. Only the sound implications are computed; proper (non-split) mono/epi classification requires composition, which is not yet registered:

    classwhat it asserts
    endoself-mapping — \(\mathrm{dom}(f) = \mathrm{rng}(f)\)
    autoan invertible endomorphism — endo and iso
    isoinvertible — currently a self-inverse (involution)
    monoleft-cancellable — \(f \cdot g = f \cdot h \Rightarrow g = h\) (here: a split monomorphism)
    epiright-cancellable — \(g \cdot f = h \cdot f \Rightarrow g = h\) (here: a split epimorphism)
    sectionsplit mono — \(f\) has a left inverse
    retractionsplit epi — \(f\) has a right inverse

    The morphism's law field is a set of process law labels served from mInstSetLawTable (the declared process laws):

    magmadica bare binary op — a magma, as monoidic is a monoid — no identity demanded
    unitan identity element — \(e \cdot x = x \cdot e = x\)
    absorbingan annihilator — \(a \cdot x = a\) for every \(x\)
    actiona monoid/group acting on a carrier — \(f(gh)x = f(g)f(h)x\)

    the declared rewrites — laws as rules

    Everything above is also the rewriter's input. A rule fires only when the operand's type declares the law that the rule consumes, and the category is the rewrite table: an algebra registered on a type licenses the rules of that type, and a type that models no such structure is left unchanged.

    rewritereadsrule
    theory_unit_removalevery theory instance of the operand's type\(\mathrm{op}(\mathrm{id}) \leadsto \varepsilon\)
    theory_involution\(\mathrm{law} \ni \mathrm{involution}\), or the declared inv role\(f \cdot f \leadsto \varepsilon\)
    law_idempotent\(\mathrm{law} \ni \mathrm{idempotent}\)\(f \cdot f \leadsto f\)
    law_absorbing\(\mathrm{law} \ni \mathrm{absorbing}\)\(g \cdot f \leadsto f\)
    law_monoidic\(\mathrm{law} \ni \mathrm{monoidic}\) + the reducer/join form\(f \cdot f \leadsto f\)
    law_poset\(\mathrm{law} \ni \mathrm{poset}\)\(\mathrm{gt}(a) \cdot \mathrm{gt}(b) \leadsto \mathrm{gt}(\max(a, b))\), \(\mathrm{lt}(a) \cdot \mathrm{lt}(b) \leadsto \mathrm{lt}(\min(a, b))\)
    inverse_cancellationanalysis.inverse\(f(a) \cdot f^{-1}(a) \leadsto \varepsilon\)
    form_map_unwrapthe stream lift map\(\mathrm{map}(f) \leadsto f\)
    derivation_contractionderivation\(\mathrm{plus} \cdot \mathrm{neg} \leadsto \mathrm{minus}\), \(\mathrm{mult} \cdot \mathrm{inv} \leadsto \mathrm{div}\)
    branch_collapsethe additive role of the operand's algebra — cut => [role => add]\(\mathrm{S}(x, \ldots, x) \leadsto \mathrm{S}(x\{n\})\) — equal terms collapse, summing the coefficients
    branch_inlinethe additive role — cut => [role => zero]\(a \cdot \mathrm{S}(b) \cdot c \leadsto a \cdot b \cdot c\), \(\mathrm{S}_{\{c\}}(b) \leadsto b\{c\}\), \(\mathrm{S}(x) \leadsto \mathrm{map}(x)\)
    law_shardform = reducer with a combiner declaring monoidic, commutative + a live peer rosterthe seed partitions, each peer folds its shard, and the master recombines the partials through the combiner (Thm 19) — sum, prod, count, order, rec sum (distributed rec merging), and a keyed group pointwise (see the deep merge)

    Most declared laws carry no rule. Five of them back a rule directly — involution, idempotent, absorbing, monoidic, poset — and floatable and blocked do not drive a rule of their own but constrain where a distribution plan may anchor (its spans). The remaining labels are classification predicates, recorded for the rewriter's guards and for reasoning, with no rewrite of their own: commutative, unit, magmadic, nilpotent, kleene, partial, prime, cyclic, zero_divisor, left_distributive, right_distributive, action. commutative is the cleanest case: a canonical form for a commutative operand would be a no-op where it is legal — a stream ({3,1,2} already equals {1,2,3}) — while for an lst it would be unsound, its order being semantic. The law stays declared (it is what licenses the inverse-pair search) without a rewrite.

    The first two generalize a ring's unit and a group's inverse to every declared structure: the unit law is read for each (op, id) role pair a theory names (add/zero, mul/one, op/id, or/zero, and/one, join/bottom, meet/top), so \(x + 0\), \(x \cdot 1\), \(x \cdot \langle\rangle\) (uri), \(x \cdot .\) (machine) and \(x \cdot \mathrm{id}\) (code) all drop, and a bare identity operation (code's \(\mathrm{id}\)) is the identity morphism. The involution law holds for every operation declared involution — neg, inv, not, reverse, conjugate — not only the additive group's.

mtron> 5.id()
==>5
mtron> 5.neg().neg()

mtron> "ab".reverse().reverse()
==>'ab'

    mtron> 6.plus(0).mult(1).neg().neg().plus(3.neg()).mult(2).div(2)

    start  noobj{0}::T  int::T  6     <j>  initial  {0}    {1}

    Only two instructions remain in the explain table: the seed and the one operation that survives. The other instructions were rewritten away:

    • plus(0) and mult(1) are the int ring's units (theory_unit_removal),
    • neg().neg() is the additive group's involution (theory_involution),
    • plus(3.neg()) folds to minus(3) (derivation_contraction), and
    • mult(2).div(2) is a declared inverse pair (inverse_cancellation).

    Direction. Every rule above either removes or preserves chain length, so a rule set that is only ever applied in that direction settles under any rewriter::T that iterates the rewrite stage to a fixpoint — the bundled fixpoint_rewriter (fixpoint_rewriter::[max=>N], bounded iterations) is one such stage, not the only one. The dual of derivation_contraction, derivation_expansion (\(\mathrm{minus} \leadsto \mathrm{plus} \cdot \mathrm{neg}\)), is deliberately not registered: it trades the length back, so the pair would alternate forever and no stage could settle. Lowering to a target that lacks the derived operation is a policy, not a law.

    the deep merge — the rec monoid a keyed fold recombines through

    + on recs is a deep merge, and sum is its fold: \(\mathrm{sum} (\{r_1, \ldots, r_n\}) = r_1 + \cdots + r_n\). The keys union, and a key on both sides merges its two values by their kind:

    the two valuestheir mergeso
    recs\(r(k) + s(k)\) — recurse, key by keya nested rec merges at every depth
    anything else, lsts too\(x \uplus y\) — appended into a streamequal values bulk, \(5 \uplus 5 = \{2\}5\); a lst stays whole

    A lst is an atom of the merge: two colliding lsts make a stream of lsts, \([1,2,3] \uplus [2,3]\), never their concatenation — the union is commutative, so its fold is defined over a stream. Rec sum declares monoidic and commutative, so law_shard distributes a rec merge as it distributes a sum of ints: each peer merges its share of the recs and the master merges the partial recs. Concatenating lst values is said by the expression, with a select's +: \([1,2,3] \mathbin{+\!\!+} [2,3]\) is [a=>[1,2,3]]==[a=>+[2,3]].

    A coefficient is a multiplicity, read the way every access reads it — the outer \(c\) multiplied into what it holds, \(\{c\}[k \Rightarrow v] = [k \Rightarrow \{c\}v]\), all the way down to the merge's atoms, where \(\{c\}v\) is \(v\)'s multiplicity in the stream (a lst's too). A bulked rec therefore merges as the copies it stands for, \(\{c\}r = r + \cdots + r\) (\(c\) times), and a fold over a stream answers what it answers over the copies.

    A weekend of dog walks makes the rules concrete. Each day files one report: dog ⇒ kilometres per trail, plus the places visited.

    mtron> /usr/walk/sat -> [mama=>[km=>[ridge=>12,lake=>5],visited=>[arroyo]],puppy=>[km=>[ridge=>12]],chelsea=>[km=>[lake=>5]]]
==>[mama=>[km=>[ridge=>12,lake=>5],
           visited=>[arroyo]],
    puppy=>[km=>[ridge=>12]],
    chelsea=>[km=>[lake=>5]]]
mtron> /usr/walk/sun -> [mama=>[km=>[ridge=>9],visited=>[acequia,mesa]],puppy=>[km=>[lake=>5]],chelsea=>[km=>[lake=>5]]]
==>[mama=>[km=>[ridge=>9],visited=>[acequia,mesa]],
    puppy=>[km=>[lake=>5]],
    chelsea=>[km=>[lake=>5]]]
mtron> */usr/walk/sat + */usr/walk/sun
==>[mama=>[km=>[ridge=>{12,9},lake=>5],
           visited=>{[arroyo],[acequia,mesa]}],

    chelsea=>[km=>[lake=>{2}5]]]

    Every rule fires in that one merge:

    • every dog is in both reports, so each dog's rec merges — and so does each km rec, one level down;
    • mama's ridge is in both: 12 and 9 append into the stream {12,9}, while mama's lake is Saturday's alone and is kept;
    • puppy's two days share no trail, so the two km recs simply union;
    • chelsea walked the same loop on both days — two equal values, which bulk to {2}5;
    • mama's visited values are lsts — atoms of the merge — so the two days' lists stream whole, {[arroyo],[acequia,mesa]}.

    The merge keeps every partial; a per-key fold reduces them. == (select) applies a pattern rec key by key — _ matches every key and a nested pattern descends — so the weekend's totals are one select away: sum reads {12,9} as \(12 + 9\) and {2}5 as \(5 + 5\), while visited=>_ keeps the stream of lists as it is.

    mtron> */usr/walk/sat.plus(*/usr/walk/sun)==[_=>[km=>[_=>sum()],visited=>_]]
==>[mama=>[km=>[ridge=>21,lake=>5],
           visited=>{[arroyo],[acequia,mesa]}],
    puppy=>[km=>[ridge=>12,lake=>5]],
    chelsea=>[km=>[lake=>10]]]

    To join the lists rather than stream them, the expression says so — a select's + concatenates the slots:

    mtron> */usr/walk/sat==[mama=>[visited=>+[acequia,mesa]]]
==>[mama=>[visited=>[arroyo,acequia,mesa]]]

    A stream of equal recs is one rec with a coefficient, and the merge reads it as the copies it stands for — the bulked sum is the explicit +:

    mtron> {[puppy=>[km=>[ridge=>12]]],[puppy=>[km=>[ridge=>12]]]}
==>{2}[puppy=>[km=>[ridge=>12]]]
mtron> {[puppy=>[km=>[ridge=>12]]],[puppy=>[km=>[ridge=>12]]]}.sum()
==>[puppy=>[km=>[ridge=>{2}12]]]
mtron> [puppy=>[km=>[ridge=>12]]] + [puppy=>[km=>[ridge=>12]]]
==>[puppy=>[km=>[ridge=>{2}12]]]

    The keyed combiner. This is how law_shard recombines a keyed fold. group([k ⇒ h]) is a homomorphism from the stream into the recs of \(h\)'s monoid, so its combiner is computed from \(h\)'s rather than declared, \(\mathrm{combiner} (\mathrm{group} ([k \Rightarrow h])) = \mathrm{sum} \cdot \mathrm{select} ([\_ \Rightarrow \mathrm{combiner} (h)])\): the peers' partial recs deep-merge, and each key folds through \(h\)'s combiner — exactly the select above. merge() bulks equal partials (two peers answering [k=>1] arrive as {2}[k=>1]), and the coefficient reading is what keeps both counted. A lst-valued fold recombines the same way: an order's sorted partials stream whole per key — a stream of runs, never their slots — and kmerge merges the runs.

    the third lift — code as a vertex (path::T, abstraction::T)

    The first two lifts put types and insts into the graph; the third puts code in. A chain lifted to path::T is a vertex whose out-edges are the rewrite rules that can move it — the rewrite graph, generated one dereference at a time, never materialized whole. Its pointwise image under \(\alpha\) is abstraction::T: the same chain with every instruction replaced by its morphism::T, i.e. value code below, type code above.

    A-priori pruning. Whether an edge is live is decided from declarations alone — no match is attempted. Each rule's guard factors into a type-part (laws, forms, adjacency of classifications) and a value-residue (operand equality, literal values); the pruner tests only the type-part, a necessary condition, so pruning a rule is a proof of identity ("no match in the abstraction, no match in the concrete") while keeping one merely licenses the real match. A rule the pruner does not know is never pruned.

    plan::T — a rewrite rule as a value

    A path::T out-edge is not a bare rule name — it is a plan: the rewrite rule itself, lifted to a first-class value. plan::T is the morphism of the rewrite category (path → path), and it is data, never a closure: a plan is introspectable and applicable wherever it is supplied.

    A plan is always the rec [name, cut, route]; what distinguishes a local plan from a distribution is what its cut names and where its route sends it:

    shapethe cut readsthe routeexample
    locala declared process law — [law => [...]] — or a theory role — [role => ...]stays local (target => none / local)law_idempotent → cut => [law => [idempotent]]; theory_unit_removal → cut => [role => id]
    distributiona form + law anchor — the laws its combiner must declareships to peers, with the combiner re-applied locallylaw_shard → cut => [form => reducer, law => [monoidic, commutative]]

    The application is a type method, not a field: lower(plan::T) is one instruction registered in catInstSet.insts(), shared by every plan. It matches the plan's cut against the path's code, applies the rewrite, and re-lifts the result to path::T. The plan carries no result λ; lower is the operator.

    A distribution plan requires peers. law_shard is live only over a non-empty peer roster: its guard reads the machine's dialed peers, and with no peer it matches nothing, so lower is the identity.     may / must — the fiber modality

    An abstraction stands for its fiber — every concrete chain that lifts to it — so the moves a path::T exposes, decided by reading the abstraction, are claims quantified over that set in one of two strengths:

    modalitythe claimexample
    must □the rule fires for every fiber member — its guard reads no valuelaw_shard on \([\mathrm{initial}, \{\ast\}\mathrm{floatable}, \mathrm{reducer}]\)
    may ◇the rule fires for some members; undecidable without valuesunit removal at \(\mathrm{plus}(\mathrm{int})\) — only the \(\mathrm{plus}(0)\) members

    Thus, the degree ordering \(\mathrm{edges} (p) \subseteq \mathrm{edges} (\alpha (p))\) holds: the abstraction licenses a move for the whole fiber when a rule's type-part matches its morphisms, and equality holds exactly when every edge is a must-edge. Refinement is edge-antitone (order-reversing) — descending the rungs (\(\mathrm{plus (int)} \to \mathrm{plus?int \le int (int{::}T)} \to \mathrm{plus} (0)\)) shrinks the fiber and discharges the ◇ into a □. A rule becomes exact at the rung whose type absorbs its residue. Counting instances rather than rules, the ordering reverses: one licensed move fans out to one concrete edge per match site, so the abstraction licenses more kinds of moves while the path licenses more copies of fewer kinds.

    Planning. The lossy lift makes the fiber \(\gamma\) of a vertex an infinite family, so no descent is made from an arbitrary abstraction. What the abstract walk computes is therefore not code but a route: a sequence of rule names, chosen in the abstraction, where the graph is small, then replayed on the path's code (path::T.obj, the γ anchor), where the values and sites exist (the path-lifting property of a fibration). Must-edges lift unconditionally; may-edges are the backtrack points, known in advance — a plan's remaining ◇-count is readable as the degree gap between the path and its abstraction. The replayed route is the derivation witness.
