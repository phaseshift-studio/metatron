https://mqtt.org/[MQTT] is a lightweight messaging protocol commonly used for IoT (https://en.wikipedia.org/wiki/Internet_of_things[Internet of Things]) applications. 
The protocol offers https://en.wikipedia.org/wiki/Publish%E2%80%93subscribe_pattern[publish-subscribe] messaging and a wildcard-based addressing scheme that conveniently maps to the URI address space.

NOTE: The inspiration for metatron's URI addressing schema was inspired by the various standards developed by the Semantic Web community and the MQTT standard developed by the IoT community. The integration of these worlds into programming language and compiler design as it applies to distributed data management is the driving force behind metatron.

[mtron]
----
*/m/iot/space/mqtt
----

The MQTT space is a client of the MQTT broker referenced by `host`. This client maintains a router-detached caching space (default is `memspace::T`) which maintains synchronization with that subset of the broker identified in the MQTT space's routing table. In the examples to follow, the pattern prefix `ha:` stands for "home automation."

[mtron]
----
mqtt::[pattern => <ha:#>,                                   /
       host    => mqtt://localhost:1883,                    /
       route   => [ha:=></home/chips>]]@/sys/space/esp32          [-- <1> --]


*ha:main_field/sensor/+.-<|[                                /
  >>temp.?<50  => print('too cold for watering'),           /
  >>humid.?>30 => print('too humid for watering'),          /
  _            => print('starting drip system').            /
                  ha:main_field/actuator/drip(minutes::25)]        [-- <2> --]

ha:main_field/actuator/+/active?subq -> sub::[on_recv=>print(_)]   [-- <3> --]
*ha:main_field/actuator/#?subq                                     [-- <4> --]
----
<1> the `mqtt::T` space maintains a subset of the larger address space of the broker.
<2> the `mqtt::T` space can be queried like a database due to mqtt persist being enabled by default.
<3> the `mqtt::T` space addresses can be subscribed to and receive updates via `inst` callbacks.
<4> query the for all subscriptions whose target uri matches `ha:main_field/actuator/#`.
