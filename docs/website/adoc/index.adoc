        <!-- MTRON -->
        <div id="mtron_feature" data-title="mtron" data-icon="images/icons/mtron-icon.svg" data-back-image="images/modal/mtron-modal.svg">
            <div class="feature-front">
                <b class="metatron-name">mtron</b> is a functional, type-safe, data flow language capable of expressing complex data transformations within a multi-model data environment
            </div>
            <div class="feature-modal">
                <p><b class="metatron-name">mtron</b> (pronounced /ɛm.trɒn/) is the primary query and transformation language for the metatron virtual machine. It provides a type-safe environment for processing data across a diverse set of spaces.</p>
                <img src="images/modal/mtron-modal.svg" class="img-fluid mb-3 icon-color" style="width: 500px; display: block; margin: auto;"/>
                 <p>
                In mtron, URIs and instructions are both first class citizens. The URI's structure is capitalized on throughout the language where, for example, query parameters encode instruction domain and range types. This leads to URIs referencing code composed of URIs which provides a unique level of software reflection without abandoning a functional structure.
                 </p>
            </div>
            <script type="text/javascript">featurePanel("mtron_feature");</script>

        <!-- URI -->
        <div id="uri_feature" data-title="fURI" data-icon="images/icons/link-icon.svg" data-back-image="images/modal/furi-modal.svg">
            <div class="feature-front">
                metatron <b class="metatron-name">objs</b> exist in a single, unified uri address space where processes can seamlessly traverse across different data sources
            </div>
            <div class="feature-modal">
                <p>The <b class="metatron-name">fURI</b> (<i>functional</i> URI) is the cornerstone of metatron's memory model. Every piece of data, regardless of its underlying storage, is addressed via a consistent URI scheme. The primary ramification is that any bit of data can refer to any other bit of data regardless of its physical location and underlying storage system and format. For instance, a line of text in a <code>.txt</code> file on a hard drive can reference some specific tag in an HTML page on the web. Atop the space-based URI graph, there exists a URI-aware machine capable of processing that data in a storage-agnostic manner.
                </p>
                <img src="images/modal/furi-modal.svg" class="img-fluid mb-3 icon-color" style="width: 500px; display: block; margin: auto;"/>
            </div>
            <script type="text/javascript">featurePanel("uri_feature");</script>
        </div>
        <!-- SPACE -->
        <div id="space_feature" data-title="space" data-icon="images/icons/space-icon.svg" data-back-image="images/modal/space-modal.svg">
            <div class="feature-front">
                data sources are logically abstracted as <b class="metatron-name">spaces</b>, where each datum has a uri address enabling the stitching together of database, file system, event, and peripheral data
            </div>
            <div class="feature-modal">
                <p>A <b class="metatron-name">space</b> is a storage and/or processing system that is responsible for maintaining some subset of the full URI address space. Spaces include but are not limited to, relational databases, graph databases, key/value stores, document stores,
                file systems, large language model catalogs, and more. Spaces can range from the small (a microprocessor's on-board memory), to the large (the world wide web).</p>
                <img src="images/modal/space-modal.svg" class="img-fluid mb-3 icon-color" style="max-height: 300px; display: block; margin: auto;"/>
            </div>
            <script type="text/javascript">featurePanel("space_feature");</script>
        </div>
        <!-- RING -->
        <div id="ring_feature" data-title="ring" data-icon="images/icons/ring-icon.svg" data-back-image="images/modal/ring-modal.svg">
            <div class="feature-front">
                the typical functional programming monad/monoid is extended with a <b class="metatron-name">"ringad"/ringoid</b> processor, where <b class="metatron-name">*</b> is function composition and <b class="metatron-name">+</b> is function branching
            </div>
            <div class="feature-modal">
                <p><b class="metatron-name">Ring theory</b> describes the underlying algebra of metatron. The virtual machine's instructions can be serially composed (<b>*</b>) and parallelly branched (<b>+</b>) to form program structures that are subject to the axioms and theorems of <a href="https://metatron.phaseshift.studio/articles/stream-ring-theory.pdf">stream ring theory</a> (a Turing Complete stream computing algebra). Ring theorems realize execution optimization strategies (bulking coefficients), program compiler rewrites (ring equalities), and evaluation semantics (parallel, reducing, and serial execution stages).</p>
                <img src="images/modal/ring-modal.svg" class="img-fluid mb-3 icon-color" style="width: 500px; display: block; margin: auto;"/>
            </div>
            <script type="text/javascript">featurePanel("ring_feature");</script>
        </div>
        <!-- MONAD -->
        <div id="monad_feature" data-title="monad" data-icon="images/icons/cluster-icon.svg" data-back-image="images/modal/monad-modal.svg">
            <div class="feature-front">
                Processes are realized as the propagation of atomic <b class="metatron-name">monads</b> maintaining a pointer to their current location in the instruction graph (program counter) and their current location in the data graph (reference in space)
            </div>
            <div class="feature-modal">
                <p><b class="metatron-name">Monads</b> provide a logical abstraction that cleanly separates the evaluation of a program from the program itself, allowing swarms of monads to operate in parallel over the same instruction/data graphs, where their collective synchronization need only occur when certain "barrier instructions" are reached. The theory of monads is applicable across many areas of applied computing, such as execution stacks, exception handling, I/O management, reflection, program traces, and state history, to name but a few.</p>
                <img src="images/modal/monad-modal.svg" class="img-fluid mb-3 icon-color" style="max-height: 300px; display: block; margin: auto;"/>
            </div>

        <div id="instset_feature" data-title="instset" data-icon="images/icons/instset-icon.svg" data-back-image="images/modal/instset-modal.svg">
            <div class="feature-front">
                metatron <b class="metatron-name">instruction sets</b> (or instset) are packages that encode a domain of discourse within a set of types, instructions, constants, rewrites, and sugars.

As a space, they support query processors, with the docq query processor being of particular importance in that it associates documentation with any obj. These objs enable the automatic generation of human-readable HTML documentation as well as agent-readable tool and skill specifications.</p>

       <!-- EMBED -->
        <div id="embed_feature" data-title="embed" data-icon="images/icons/storage-icon.svg" data-back-image="images/modal/embed-modal.svg">
            <div class="feature-front">
                A data structure can have an inter- or intra-space <b class="metatron-name">embedding</b> such that each subset of its form can take advantage of the respective time-space tradeoffs of the underlying storage system.
            </div>
            <div class="feature-modal">
                <p>A data structure such as a vertex in a graph can have many incoming and outgoing edges with different edge labels and properties. Such diversity entails not all edges will require the same read/write performance characteristics. In metatron, it's possible to <b class="metatron-name">embed</b> one edge set in a space optimized for fast retrievals (e.g. an in-memory space) and another subset in a space optimized for static, long-term storage (e.g. a disk-backed space). Other considerations may include the indices associated with a space and whether certain properties of an edge can be indexed for non-linear access.</p>
                <img src="images/modal/embed-modal.svg" class="img-fluid mb-3 icon-color" style="max-height: 300px; display: block; margin: auto;"/>

        <!-- TYPE -->
        <div id="type_feature" data-title="type" data-icon="images/icons/type-icon.svg" data-back-image="images/type-diagram.svg">
            <div class="feature-front">
               objs are constrained using a <b class="metatron-name">structural type system</b> that can express inherited, refined, dependent, and recursive types with constructs for expressing cardinality, optionals, generics, predicates, and more.
            </div>
            <div class="feature-modal">
                <p>The <b class="metatron-name">structural type system</b> of metatron ensures that the label ascribed to an obj's form (its nominal type) is but a secondary concern relative to the obj's relational structural within the larger data space as a whole. If an obj meets all the specified constraints of a defined type, then it is of that type and can be processed by instructions and composed within larger types requiring said type. From this vantage point, many homomorphic transformations can be realized that render the distinctions between a row in a relational database, a tag in an HTML document, a vertex in graph, and a value in a key/value store to be simply differences of name, not function.</p>
                <img src="images/type-diagram.svg" class="img-fluid mb-3 icon-color" style="max-height: 400px; display: block; margin: auto;"/>

Hundreds of thousands of monads can traverse vast swathes of the data landscape, across different physical machines, all in pursuit of a solution to a problem that has been formally captured within the structure of an obj called code.</p>

Together, the pulse of expanding and contracting processes forms the heartbeat of the computation.</p>

Similarly, <b class="metatron-name">WebSocket space</b> offers session-based interactions via a simple string-based mtron evaluation protocol, or an MCP server, or a custom protocol if needed.</p>
